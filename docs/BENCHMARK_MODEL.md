# VIVUM — пакетные benchmark и нормативы

## Два уровня данных
### Массовый хронометраж
Монтажник работает с 7–9 укрупнёнными этапами. Результат используется для:
- фактической производительности рабочего пакета;
- сравнения объектов/бригад/условий;
- анализа потерь;
- проверки, что сумма детальных норм реалистична.

Массовый замер не публикует детальные нормы операций автоматически.

### Исследовательский хронометраж
Выбранные наблюдения раскладываются на детальные операции `EL-RI-xxx-yy` и соответствующие количественные драйверы.
Только эти данные могут напрямую наполнять `NormCard` операции.

## Почему нельзя автоматически делить укрупнённый этап
Одна группа может содержать операции с разными драйверами. Например, подготовка блока может зависеть от числа блоков, а установка коробок — от числа подрозетников. Один общий таймер не определяет вклад каждой операции.

## Пакетный benchmark
`PersonMinPerPrimary = ProductivePersonMin / PrimaryQuantity`.

Для серии показываются минимум:
- sample size;
- median;
- P25/P75;
- min/max;
- median loss ratio;
- список исходных measurementId.
## Статус результата
Анализатор присваивает `CANDIDATE_REVIEW_REQUIRED` / `BENCHMARK_ONLY` и всегда `normPublicationAllowed=false`.

Это сознательная защита: статистический benchmark должен быть сначала проверен инженером на сопоставимость технологии, основания, инструмента и состава работ.

## Потери
Пакетный benchmark использует только производительное человеко-время. `T_loss` анализируется отдельно и не прибавляется к норме.

## Файл
`scripts/analyze_measurements.py` читает CSV, экспортированный приложением v0.2.3, и формирует JSON-анализ без изменения нормативной базы.
