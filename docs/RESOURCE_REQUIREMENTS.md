# VIVUM — ресурсные требования рабочего пакета v2

## Назначение
Ресурсная модель отвечает на два разных вопроса:
1. что должно быть доступно до допуска пакета к работе;
2. что и в каком количестве должно попасть в производственную себестоимость.

Эти вопросы связаны, но не идентичны.

## Режимы требований
- `REQUIRED` — конкретный материал обязателен.
- `ONE_OF` — выбирается ровно один допустимый вариант технологии/материала.
- `ONE_OR_MORE_OF` — выбирается один или несколько ресурсов, например состав кабельного пучка.
- `REQUIRED_CAPABILITY` — необходима функция инструмента; конкретная модель может отличаться.
- `CONDITIONAL` — ресурс нужен только при выполнении условия, например средства доступа по высоте.

## Примеры пилота
`EL-RI-001`: установочная коробка обязательна; монтажный состав выбирается из алебастра, гипсовой штукатурки или иного согласованного состава.

`EL-RI-003`: выбирается один фактический тип кабеля из номенклатуры пилота; площадки, стяжки, гвозди и газ относятся к технологии крепления.

`EL-RI-004`: допускается один или несколько типов кабеля, потому что общий пучок может быть смешанным.
## Нормирование расхода
Наличие материала в чек-листе не означает, что его расход уже нормирован.
Для каждого требования хранится `consumptionStatus`:
- `DRAFT` — связь с драйвером задана, но ещё не утверждена как норма расхода;
- `MEASURE_REQUIRED` — нужен фактический замер расхода;
- `RESERVE_RULE_REQUIRED` — нужна политика технологического запаса;
- `CONSUMPTION_RULE_REQUIRED` — нужна отдельная норма расхода;
- `FORMULA_REQUIRED` — нужна формула из нескольких драйверов.

До утверждения правила расхода автоматическое количество для сметы не формируется.

## Защита от ложной комплектности
Плоская ресурсная матрица v1 сохраняется для поиска/отчётности. Для допуска и автоматизации используется v2, потому что она различает обязательные ресурсы, альтернативы и условные позиции.

Файл: `data/package_resource_requirements.v2.json`.

## Отложенные проектные ресурсы
Некоторые ресурсы нельзя достоверно вывести только из объёма рабочего пакета.

Для `EL-RI-006` ГМЛ имеет режим `FUTURE_REVIT_CONNECTION_MODEL`: типоразмер и количество должны прийти из будущей модели электрических соединений.

ТТК имеет режим `DERIVED_FROM_REQUIREMENT`: она рассчитывается только после определения конкретной ГМЛ и правила технологического запаса.

Это не ошибка комплектности. До появления источника проектных данных такие позиции намеренно остаются `NOT_DERIVED` и блокируют полную автоматическую себестоимость соответствующего ресурса.
