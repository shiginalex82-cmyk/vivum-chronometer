# VIVUM — будущий контракт коммутации Revit

Статус: **DEFERRED / CONTRACT ONLY**. Модуль проектирования электрики сейчас не разрабатывается.

## Назначение
Когда VIVUM/SHIGIN начнёт проектировать электрику в Revit, ресурсный расчёт коробки должен получать не ручное количество ГМЛ, а фактическую топологию соединений.

Цепочка данных:
`Revit box → входящие кабели → жилы → connection groups → GML → TTK → BOM / себестоимость`.

## Connection group
Одна группа — набор жил, которые электрически соединяются между собой в одно соединение. Количество кабелей само по себе не равно количеству ГМЛ.

Для группы нужны минимум:
- ID коробки Revit;
- ID группы соединения;
- ссылки на кабели/жилы;
- сечение каждой жилы;
- материал проводника;
- электрическая функция, если она определена моделью.

## ГМЛ
Количество ГМЛ = количество соединений, для которых технология предусматривает отдельную гильзу.

Типоразмер выбирается по фактическому составу группы жил и таблице/правилу конкретного производителя. Упрощённая формула `сумма сечений = размер ГМЛ` не считается достаточной без подтверждённого каталога производителя.

До появления Revit-топологии статус: `PROJECT_MODEL_REQUIRED`.
## ТТК
ТТК не нормируется напрямую «на соединение».

После выбора конкретной ГМЛ система должна получить её геометрию/типоразмер, выбрать совместимый диапазон ТТК и рассчитать длину:
`длина ГМЛ + запас перекрытия изоляции до ГМЛ + запас после ГМЛ`.

Числовой запас пока не утверждён и не подставляется автоматически.

До определения ГМЛ статус ТТК: `UPSTREAM_RESOURCE_REQUIRED`.

## Интеграционный принцип
Текущий хронометраж и сметное ядро не должны создавать ручную параллельную модель соединений.

Источник истины в будущем — проектная электрическая топология Revit/SHIGIN. PM хранит полученный результат и ссылки на версию проектной модели/правила выбора.

JSON-контракт: `schemas/future_electrical_connection_model.schema.json`.
